# 用餐身分管理

## 接待題限一般身分（本機已實作，待部署）

- 只有身分代碼 `general` 的「一般」回答開家接待與接機接待。學生、兩種兒童及自訂身分不顯示這兩題，資料庫存「否」；公開頁與後台共用此規則。
- 身分別尚未選擇時不顯示接待題。身分為空值的舊登記不回填，修改時預先帶入「一般」。
- 非一般身分不受「開家接待者」「接機者」報名對象限制。
- 既有學生與自訂身分的接待答案由 `202611100004_hosting_general_only.sql` 改為「否」並寫審計紀錄；部署前先以 `supabase/testing/preview-hosting-general-only.sql` 確認受影響名單。決策見 [需求討論與決策紀錄](需求討論與決策紀錄.md)「接待題限一般身分、提醒區塊與查詢結果版面」。

## 身分標籤設定（本機已實作，待部署）

- 管理員可設定各身分的「顯示標籤」與底色，使用完整選色器或輸入六位 HEX 色碼。文字依底色自動使用黑色或白色。
- 標籤文字沿用身分名稱，套用到後台報名清單、詳情與兒童統計。關閉標籤不影響統計人數與 CSV；關閉兒童身分標籤時，統計畫面只顯示兒童總數，國小／學齡前分項仍保留在 CSV。
- 學齡前、國小、學生預設開啟並沿用原底色；其他既有身分與新建身分預設關閉。
- 部署順序：`202611100003_identity_badges.sql` → `staff` Edge Function → 前端。舊版後台儲存身分時未帶標籤欄位，會保留原設定。
- 測試資料庫可執行 `supabase/testing/verify-identity-badges.sql`，驗證預設、儲存、舊版保留設定、無效色碼與審計紀錄；測試資料會回滾。

## 後台操作

活動費用採 B 版排版：左側為各身分價格表，每種身分獨立一列；右側為管理設定，放置實際每人成本與排序。手機版改為上下排列，新增身分時只增加價格表的列數。

- 管理員在「身分別」新增、修改名稱、停用或刪除用餐身分，並設定「開放報名者選擇」。未開放的啟用身分只能由後台指定。
- 已有登記使用的身分不能刪除，只能停用；停用後既有登記可保留，其他登記不能新選用。
- 一般與兒童為系統保留身分，可改名稱，不能刪除、停用或關閉公開選擇。兒童仍由表單的兒童勾選欄位控制，成人不會看到兒童身分選項。
- 活動新增／編輯畫面依身分清單產生價格欄位。每種身分獨立計價，所有欄位空白均為「未設定」，表示尚未提出收費；不沿用一般價，也不當作 0。只有填 0 才表示免費。停用身分的價格仍可調整，以服務既有登記。
- 修改身分名稱後，既有登記、統計與匯出使用新名稱；修改價格後，所有登記使用最新價格，不保存報名當時價格。

## 登記表單

- 勾選參加至少一個類型為 `meal` 的公開活動時，顯示並要求用餐身分，與是否設定學生價無關。從未回答過的登記沒有參加用餐時存一般。
- 同時勾選「兒童」時，自動帶入兒童身分，不能改選其他身分。
- 沒有參加用餐活動時，隱藏且不要求填寫身分。既有資料庫身分保留，之後可繼續使用；畫面與 CSV 的身分文字只在參加用餐時顯示。
- 既有一般／學生保留，兒童登記轉為兒童，未填身分者補為一般。
- 後台身分選項與活動的參加／不參加選項共用欄寬，更多身分往下一列排列。

## 資料結構與部署

`registration_identities` 儲存穩定代碼、顯示名稱、啟用與公開選擇狀態；`registrations.meal_identity` 以外鍵引用代碼。`activity_identity_prices` 以活動與身分代碼儲存價格，既有學生價會搬入。以後新增身分不必新增欄位或 migration。

部署順序：舊版頁面只在有學生價的用餐問身分，套用 migration 後每個用餐都要身分，所以正式站依 [正式環境setup](正式環境setup.md) 9-3 維護流程，先關閉登記再更新。

1. 確認已套用 `202611090001_child_registration.sql`，再依序套用 `202611090002_registration_identities.sql`、`202611090003_independent_identity_prices.sql`；後者解除學生價須先填一般價的限制。
2. 更新 `registration` 與 `staff` Edge Functions。
3. 發佈 `site` 靜態頁面，重新整理已開啟的後台與報名頁。
4. 在測試專案執行 `supabase/testing/verify-registration-identities.sql` 與 `verify-independent-identity-prices.sql`；腳本使用既有管理員，建立虛構的身分、活動與登記，結束回滾。正式專案不可執行這兩支腳本。

資料表不開放 anon／authenticated 直接存取；寫入透過既有 Edge Function 與 service-role RPC，管理操作檢查管理員權限，身分與價格的變更以 `reference.saved`／`reference.deleted` 寫入 `audit_events`。

特會本身的實際成本尚未公布，目前還不好計算收費。報名費 $250 暫不由系統計算，待成本公布後再討論計算規則；各活動用餐身分價格仍依現有設定處理。

## 各活動兒童統計

各活動表在「其中學生」右側增加「其中兒童」，計算有效登記中參加該活動且勾選兒童的人數，適用所有活動，不受兒童價設定影響。統計 CSV 同步包含此欄。

## 空白價格與合計

一般價空白保留 NULL；其他身分沒有價格紀錄表示未設定，用餐身分未回覆的人同樣沒有價格。費用合計與補貼只加總已設定的價格，未設定的不計入，也不當作 0 或套用一般價，並在金額後註明哪些身分未計入，例如「NT$800（兒童未計入）」；尚未回覆身分的人寫「未回覆身分者」，活動完全沒有價格時寫活動名稱。統計摘要與「各區」表只顯示已設定費用的加總金額，不加註明；註明只出現在「各活動」表。全部都未設定時顯示「—」，與未設定成本相同。補貼只算費用已設定的人：已設定人數 × 實際每人成本 − 已設定費用。統計 CSV 與畫面相同。登記 CSV 的「預估應付餐費」只放已設定費用的加總數字（全部未設定時為「未設定」），「餐費未計入的活動」列出未計入的活動名稱。未參加任何活動時合計為 0。價格補上後重新整理統計即可，不需其他處理。
