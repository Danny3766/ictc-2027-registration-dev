# 開家與接機的公開填寫身分設定

2026-11-11 已確認 Q1～Q16；依使用者最新指示，直接在 `feat/conference-import-status` 實作，不另開分支。先記錄本文件與需求決策，再改程式。

## 已確認決策

- 開家、接機分開設定身分複選框；各題總開關勾選後才顯示設定區。關閉後保留選擇；開放時至少選一種身分。
- 首次部署兩題都只選一般；新身分預設不選。兩種兒童身分均可開放。
- 清單列出啟用且公開可選身分；已選但停用／僅後台可選的仍列出並標註，未選的不列出。
- 公開新增及修改只有總開關開啟且身分被選中才可填，適用題目須回答；查詢仍可看既有答案，不可填時提示目前身分未開放修改。
- 後台可替任何身分填寫／修改，即使公開調查關閉。後台代填與本人填答都是有效答案；公開查詢／修改帶出後台內容。
- 取消身分資格保留原答案，不批次清空，也不因此改匯入狀態。
- 公開頁與後台把登記的身分從可填改成某題不可填的身分（例如一般改學生）並儲存時，該題直接存成有效的「否」，不保留原答案，即使同次送出其他答案；兩題各自判斷，按一般答案異動規則改匯入狀態，原值留在稽核紀錄。之後改回可填身分時這個否就是答案，不必重答。身分不變時後台仍可替不可填身分填答。從不可填身分改成另一個不可填身分不變動答案。（2026-11-11 使用者補充決定，取代先前的「失效並保留原答案」）
- 公開頁同一次編輯切出再切回、尚未儲存時，該題畫面選擇清空須重新回答（後台不清空）；不可填身分的失效舊答案不顯示；取消整次編輯不更動已存資料。兩題各自判斷。
- 新增不適用者不存成實際回答否。舊系統自動否不算本人答案；取得填寫資格後應顯示未回答，統計及匯出不列入已回答否。
- 未開放填題身分繼續豁免對應 hosting／pickup 活動資格；取得資格後依有效答案判斷。活動前置條件仍適用。
- 設定異動本身不改大會匯入狀態；身分及有效答案實際異動沿用匯入規則。失效後重新確認也屬未回答 → 已回答。

## 待決定（2026-11-11 code-review 提出，尚未實作）

1. **公開頁同一次編輯、未儲存的切出再切回**：目前清空該題並要求重答；題目關閉時送出 `reset` 標記，把已存答案改為失效。另一個做法是比照「儲存才算改身分」，未儲存的來回切換不動答案，可移除 `reset` 標記與相關程式。現行做法另有一個缺口：頁面判斷題目開放、伺服器其實已關閉時，頁面不送 `reset`；使用者重選相同答案，答案仍維持有效，不會要求重答。改成不動答案後，這個缺口也一併消失。
2. **身分加進某題可填清單時的提醒**：例如把學生加進開家清單後，原本因不可填而豁免開家限定活動、又沒有有效答案的學生，會變成不符資格；下次公開儲存時會被報名對象規則擋下，統計也列為不符對象。後台修改活動報名對象時會先提醒受影響人數，修改身分清單時沒有。是否比照提醒，待確認。

## 實作與驗收範圍

1. migration：分開保存身分清單、答案有效性與原答案；查核 audit 辨別舊自動否，保留原值；後端必填、不可填保護、身分切出存否、audit、資格與聚合統計一致。
2. API：公開與 staff 設定及單筆回應、儲存欄位；處理公開頁載入後設定改變。
3. 介面：後台複選設定、公開新增／查詢修改、後台代填與兒童；統計及 CSV 同步。
4. 測試：兩題獨立、多身分、兒童、開關與空清單、停用身分、有效及自動答案、同次與跨次身分切換、後台代填、匯入狀態、權限與設定競態。

## 資料與相容性

- `site_settings.hosting_identity_codes`、`pickup_identity_codes` 各自保存身分清單，預設只有 general。管理員調整總開關與清單時使用同一交易；設定中的身分不可直接刪除，須先取消勾選。
- 兩張接待回答表各增加 `answer_valid`。有效答案供資格、容量、統計及 CSV 使用；失效原值仍保留，查詢可看先前紀錄。無有效答案且身分不在該題清單者為不適用，不算已回答否。
- migration 依目前身分與 audit 回填：非一般的舊自動答案、一般身分最後仍是 child_updated／maintenance 產生的否，標為待確認。實際已回答否保留有效；遇到「原值也是否、無法證明曾重新確認」時要求重答，不猜測本人已確認。
- 公開儲存改由 `update_registration_survey_result` 在同一交易回傳有效答案；畫面以伺服器結果為準，避免編輯途中設定變更後沿用過期狀態。
- 失效只來自舊資料回填與同次切出再切回：同次編輯切出再切回會清除該題畫面選擇；若題目關閉，送出 `reset` 標記保存重答要求。取消整次編輯不送出任何異動。明確重新填答後恢復有效性，即使答案仍為否。
- 後端共用答案生命週期，保留原有姓名／區唯一性、限流、截止與權限；公開操作關閉時，在查找姓名前一致拒絕。統計一次取得兩份身分清單，不逐筆查詢設定。

## 部署順序

依正式環境維護流程先關閉登記，再依序：

1. 套用 `supabase/migrations/202611110003_survey_identities.sql`，確認初始兩題只選一般。回填保留原答案與最後匯入資訊，不批次改匯入狀態。
2. 更新 `supabase/functions/registration/index.ts` 與 `supabase/functions/staff/index.ts`。
3. 更新網站，重新整理已開啟頁面，驗收後恢復原本的登記開放狀態。管理員再依需求選擇公開填寫身分。

新前端依賴新欄位與 RPC，不能先發布前端。遠端尚未部署。
