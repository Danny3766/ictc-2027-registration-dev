# GitHub 公開內容機敏資料審查準則

本準則適用於推送至公開 GitHub repo 前的 staged 變更。預設採嚴格審查：只要資訊是否適合公開尚未確認，就先視為不得公開，暫停提交或推送，確認用途或移除後再檢查。

## 審查範圍

以 Git index 中已 stage 的檔案與內容為準，逐一檢查新增、修改、重新命名與刪除項目。另確認本機設定、測試產物和其他不應追蹤的檔案沒有被強制加入。

審查不只搜尋密鑰字串，也要閱讀設定、程式、migration、seed、文件、範例、測試資料、註解與檔名。確認 ignore 規則存在仍不夠，必須確認敏感檔沒有出現在 staged 清單。

## 預設不得公開的內容

- 認證與存取憑證：密碼、資料庫連線字串、API secret、service role key、JWT、access token、refresh token、私鑰、pepper、加密金鑰、備援碼及任何可重建憑證的片段。
- 個人與可識別資料：真實姓名、電話、Email、住址、帳號、身分證或護照資料、可回推個人的測試資料，以及含這些資料的 log、截圖、備份、CSV、匯出檔或測試報告。
- 非公開環境資訊：正式或測試 project reference、資料庫主機名稱、內部網域與 IP、公司或住家路徑、未公開部署網址、管理介面連結、組織專用帳號名稱及環境拓樸。
- 未核准的營運資訊：未公布的活動或場地安排、供應商與餐廳、內部名單、容量、價格、時程、維護流程、事故處理方式及尚未公開的產品決策。
- 可降低攻擊成本的安全細節：未修補弱點、可直接重播的請求、管理操作方式、限速或封鎖門檻、繞過條件、權限配置與防護例外。公開必要的執行設定前，須確認它是產品所需且已核准的設計。

## 有條件可公開的內容

- 活動名稱、日期、地點、地址與對象，只有在已決定要讓登記者知道時才視為公開資訊。使用者明確核准的公開活動消息不列為機敏資料。
- 公開 API URL、publishable key、範例設定與公開程式碼可以出現在 repo，但必須確認不含 secret，且資料庫權限、RLS 與服務端驗證已符合用途。Publishable key 雖可公開，仍須確認其權限只涵蓋預期公開操作。
- 公開登記的限流門檻、預估尖峰人數與會場 Wi-Fi 比例：專案負責人 2026-11-07 核准記錄於[需求討論與決策紀錄](需求討論與決策紀錄.md)「2026-11-07 上線尖峰限流」一節，日後調整也記在該節。偵測條件與繞過方式仍不得公開。
- `verify_jwt = false` 等公開端點設定不是憑證，但會揭露安全設計。只有在功能確實需要未登入訪客存取，且 Function 自行執行必要驗證時，才可保留；審查紀錄須註明理由與服務端防護。
- 未發布旗標、註解或範例名稱不代表內容安全。公開 repo 的讀者仍能讀到所有已提交內容，因此未核准的 seed、範例、註解與 migration 一律按公開內容審查。

## 審查流程

1. 列出 staged 檔案與狀態，確認範圍符合預期；不要只看 `git diff`，要看 `git diff --cached`。
2. 檢查 staged 檔案名稱與內容，搜尋常見憑證格式、連線字串、個資、主機與路徑，再逐一閱讀相關設定、資料與程式碼。掃描器沒有命中不代表安全。
3. 對每項公開資訊判斷：它是否真的是使用者已核准公開的內容？是否會增加冒用、定位、社交工程、猜測或攻擊能力？是否存在更少揭露的表示方式？
4. 發現未核准或用途不明的資料時，停止提交／推送，移除或改用無法回推真實環境的 placeholder，再重新檢查 staged 版本。
5. 檢查完成後回報範圍、命中項目、判斷理由、未能驗證的部分與最終結論。不要在報告、終端輸出或對話中重複貼出 secret 值。

## 建議檢查命令

```powershell
git status --short
git diff --cached --name-status
git diff --cached --check
git diff --cached
git check-ignore -v site/config.js .env .env.local
```

若檔案曾經 stage，即使後來加入 `.gitignore` 仍可能留在 index；以 `git status --short` 與 `git ls-files --stage <path>` 確認追蹤狀態。對疑似憑證只回報檔案與欄位名稱，不輸出其值。

## 判定標準

- **可公開**：沒有未授權機敏資料；所有公開資訊均有明確用途與核准依據；必要的安全設定已說明理由，且不依賴隱藏前端或 repo 內容保護資料。
- **暫停公開**：找到任何憑證、個資、非公開環境資料、未核准營運資訊，或安全設定與資料用途尚未釐清。移除或取得明確公開核准後，重新檢查 staged 內容。

審查結果只對當次檢查的 staged snapshot 有效；stage、修改、合併或重新產生檔案後，需重新審查。
